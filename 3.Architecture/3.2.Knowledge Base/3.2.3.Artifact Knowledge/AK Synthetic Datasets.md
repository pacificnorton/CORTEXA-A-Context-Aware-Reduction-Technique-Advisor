# Dataset Generation

## Why Dataset Generation?

The objective of CORTEXA is to characterize the behaviour of data reduction methods under controlled analytical conditions. Using only real-world datasets would provide limited coverage of possible dataset characteristics and would make it difficult to isolate the influence of specific factors such as linearity, normality, feature composition, or dataset scale.

Synthetic dataset generation addresses these limitations by enabling:

* **Exhaustive coverage** of admissible analytical contexts.
* **Controlled manipulation** of statistical and structural properties.
* **Systematic evaluation** of reduction methods under comparable conditions.
* **Reproducibility** through deterministic generation procedures.
* **Isolation of causal effects**, ensuring that observed differences in reduction behaviour can be attributed to dataset characteristics rather than uncontrolled data artefacts.

For these reasons, the Knowledge Base of CORTEXA is constructed using synthetic benchmark universes specifically designed for classification and regression tasks.

---

# Dataset Generation for Classification

## Overview

The classification benchmark universe is designed to provide exhaustive coverage of all admissible dataset profiles considered by CORTEXA.

Among the 48 theoretically possible profile combinations, 28 remain after eliminating unsupported configurations according to reduction-method applicability constraints. All admissible profiles are retained to avoid sampling bias and to ensure complete coverage of the analytical space.

For each profile:

* Four noise levels are generated;
* Four linearity magnitudes are randomly sampled;
* Each configuration is replicated three times.

Reproducibility is ensured through deterministic NumPy PCG64 seeding:

$$
\text{seed}(p,k)=3000+p_{\text{index}}+20k
$$

where:

* $p_{\text{index}}$ denotes the profile identifier;
* $k$ denotes the replication index.

---

## Dataset Profile Dimensions

Each dataset profile is defined through the following dimensions:

| Characteristic   | Possible Values                 |
| ---------------- | ------------------------------- |
| Linearity        | Linear / Non-linear             |
| Normality        | Gaussian / Non-Gaussian         |
| Feature Type     | Numerical / Categorical / Mixed |
| Feature Size     | Small / Large                   |
| Observation Size | Small / Large                   |
| Analytical Task  | Classification                  |

---

## Dataset Size Generation

Dataset scale is controlled through two binary dimensions:

* Observation size: $(O_S, O_B)$
* Feature size: $(F_S, F_B)$

These dimensions allow the construction of datasets representing both low-dimensional and high-dimensional analytical scenarios.

---

## Feature-Type Generation

Feature composition follows the specification imposed by the dataset profile.

### Numerical Datasets

Numerical features are generated directly.

### Categorical Datasets

Categorical variables are generated by discretizing latent Gaussian variables into:

$$
K_j \in {2,3,4}
$$

categories while preserving the dependency structure.

### Mixed Datasets

Mixed datasets contain equal proportions of numerical and categorical variables.

---

## Distributional Control

When the profile requires Gaussian data, features are generated from multivariate normal distributions.

When normality is not required, one of the following transformations is selected with equal probability:

* Log-normal transformation;
* Exponential transformation;
* Power transformation;
* Outlier injection.

These distortions produce controlled departures from Gaussian assumptions while preserving profile consistency.

---

## Linearity Control

The linearity parameter $\ell$ controls the dependency structure between variables.

### Linear Profiles $(\ell = 1)$

Block-structured covariance matrices are generated, producing strong linear relationships between groups of variables.

### Non-Linear Profiles $(\ell = 0)$

Non-linear transformations are introduced to create complex dependencies that cannot be adequately represented through linear correlations.

This mechanism enables systematic evaluation of reduction methods under varying relationship structures.

---

## Noise Injection

Multiple noise levels are introduced during generation in order to evaluate the robustness of reduction methods under progressively degraded data quality conditions.

The combination of profile dimensions, noise levels, linearity settings, and replications forms the complete synthetic benchmark universe used during Knowledge Base construction for classification.

---

# Dataset Generation for Regression

## Overview

The regression benchmark universe is designed to characterize reduction-method behaviour under controlled regression-oriented analytical contexts.

The framework generates:

* 120 distinct dataset contexts;
* 5 independent realizations per context;

resulting in a total of:

$$
120 \times 5 = 600
$$

synthetic regression datasets.

Each generated dataset is associated with a context vector:

$$
\mathbf{p}(\mathcal{D})
$$

that records the statistical and structural properties used during generation.

---

## Dataset Profile Dimensions

Regression contexts are defined through combinations of:

| Characteristic    | Possible Values                 |
| ----------------- | ------------------------------- |
| Linearity         | Linear / Non-linear             |
| Multicollinearity | Low / High                      |
| Normality         | Gaussian / Non-Gaussian         |
| Feature Type      | Numerical / Categorical / Mixed |
| Feature Size      | Small / Large                   |
| Observation Size  | Small / Large                   |
| Analytical Task   | Regression                      |

---

## Linear Regression Contexts

When linearity is required, datasets are generated using the `make_regression` function from Scikit-Learn.

This procedure guarantees:

* A known linear relationship between predictors and target;
* Controlled signal-to-noise conditions;
* Compatibility with classical regression assumptions.

The generated datasets therefore serve as a stable baseline for evaluating the effects of data reduction.

---

## Multicollinearity Control

To introduce controlled correlation structures, a covariance matrix

$$
\Sigma \in \mathbb{R}^{d\times d}
$$

is generated.

Because arbitrary covariance specifications may produce invalid structures, the matrix is projected onto the positive semi-definite cone through eigendecomposition:

$$
\Sigma = Q\Lambda Q^{\top}
$$

with corrected eigenvalues

$$
\Lambda'*{ii}=\max(\Lambda*{ii},\varepsilon)
$$

where

$$
\varepsilon=10^{-8}.
$$

The corrected covariance matrix becomes:

$$
\Sigma_{\text{PSD}}=Q\Lambda'Q^{\top}.
$$

This guarantees valid variances and coherent correlation structures.

---

## Correlation Matrix Construction

The covariance matrix is transformed into a correlation matrix:

$$
R=D^{-1/2}\Sigma_{\text{PSD}}D^{-1/2}
$$

where

$$
D=\mathrm{diag}(\Sigma_{\text{PSD}}).
$$

A Cholesky decomposition

$$
R=LL^{\top}
$$

is then used to impose the desired dependency structure on the generated features.

This procedure enables precise control of multicollinearity while preserving the imposed predictive signal.

---

## Distributional Control

Features are subsequently rescaled to heterogeneous ranges.

When Gaussianity is not required, non-normal distortions are introduced to relax standard regression assumptions.

All variables are finally normalized to:

$$
[0,1]
$$

to ensure comparability of scale-dependent regression metrics such as RMSE and MAE across datasets.

---

## Noise Injection

Measurement noise is introduced into:

* The target variable;
* A subset of predictor variables.

This simulates realistic observation errors and allows the evaluation of reduction methods under varying robustness conditions.

---

## Categorical and Mixed-Type Data

For contexts involving categorical or mixed data:

* Selected continuous variables are discretized;
* Variables are transformed into between 2 and 4 ordered categories.

This produces datasets compatible with mixed-type regression scenarios while preserving the intended dependency structure.

---

## Knowledge Base Registration

Each generated dataset is stored together with its associated context vector:

$$
\mathbf{p}(\mathcal{D})
$$

within the Knowledge Base.

This traceability mechanism ensures that every observed reduction behaviour can be linked to a precisely defined and reproducible analytical context, enabling systematic comparison, behavioural analysis, clustering, and Pareto-based trade-off identification.
